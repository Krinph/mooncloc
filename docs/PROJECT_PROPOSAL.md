## 1. 项目名称

**mooncloc** — MoonBit 生态的代码统计与圈复杂度分析工具

## 2. 项目简介

mooncloc 是一个用 MoonBit 实现的 cloc 风格代码统计工具，同时提供库 API 与命令行工具。
它递归扫描目录树，按语言统计代码行、注释行、空白行与混合行，计算每个文件的圈复杂度，
并输出注释率、复杂度密度、最复杂文件等健康指标，支持表格 / JSON / CSV / Markdown 四种输出格式。
项目为**原创实现**，已完整落地（见仓库），非仅规划。

## 3. 项目方向与通用性说明

- **方向**：开发者工具 / 工具库（对应黑客松「开发者工具：解释器、运行时、LSP、CLI 与开发体验工具」方向）。
- **通用性**：不依赖任何特定业务，作为通用工程质量分析基础组件，可服务于 MoonBit 生态中
  任意项目的规模度量、代码体检与 CI 质量门禁；同时通过语言定义表支持 45 种主流语言，
  对非 MoonBit 项目同样可用，具备跨语言通用价值。

## 4. 预期使用场景（≥3 个）

1. **黑客松/开源赛事有效代码量证明**：参赛者与评审用 `mooncloc` 统计项目代码行、注释行，
   量化"有效 MoonBit 代码量"（本赛事官方即以代码规模为参考），替代人工数行。
2. **代码审查前的质量体检**：开发者对仓库运行 `mooncloc --all`，查看注释率、每百行复杂度、
   最复杂文件，快速定位需要重构的高复杂度模块。
3. **CI 质量门禁**：在 GitHub Actions 中调用 `mooncloc --format json`，解析 `health` 段，
   对复杂度密度或注释率设置阈值，超限即失败，防止代码质量退化（本项目自身 CI 已 dogfood 该用法）。
4. **多语言技术栈盘点**：对混合语言仓库（如含 MoonBit/JS/Python 的前后端工程）一键生成
   语言分布统计表与 JSON 报告，用于技术栈审计与成本评估。

## 5. 拟实现的核心功能（已全部实现）

1. 行级统计引擎：按语言剥离注释与字符串字面量（行注释、块注释、嵌套块注释、多行字符串、
   raw 字符串、shebang），正确分类代码/注释/空白/混合行；
2. 45 种语言定义表（MoonBit 优先，覆盖 C/C++/Rust/Go/Python/JS/TS/Java 等）；
3. 圈复杂度分析：统计 `if/elif/match/for/while/loop/guard/catch/case/when/switch` 及 `&&`、`||`、`?` 分支点；
4. gitignore 风格排除规则（`*`、`?`、`**`、目录模式、锚定模式）与内置噪音目录排除；
5. 健康指标：注释率、每百行复杂度、最复杂文件排名（`most_complex_files` / `comment_ratio` 等公开 API）；
6. 四种输出格式：对齐表格、JSON（含 health 段）、CSV、Markdown，支持语言过滤与逐文件明细；
7. CLI + 库双层 API，可用 `moon run cmd/main` 直接运行，也可 `moon add Krinph/mooncloc` 作为库嵌入。

## 6. 原创性说明

本项目为**原创项目**：统计口径与功能设计参考通用工具 cloc（GPL 许可，仅参考其功能与口径，
未使用其代码，无移植关系）；语言识别规则表依据各语言公开语法事实整理；不依赖、不复制
MoonBit 生态中任何既有项目。

## 7. 开源许可证

采用 **Apache-2.0**（OSI 认可），根目录 `LICENSE` 完整；无任何第三方代码依赖或许可证冲突。

## 附：章程建议回应的核心问题

### 一、项目价值与生态定位

- **痛点**：MoonBit 生态（2026 年 11 月）已涌现大量库与工具，但缺少代码统计/复杂度分析工具——
  开发者无法量化项目规模与质量，评审无法客观度量"有效代码量"，CI 缺少质量门禁手段。
- **生态位**：补齐"开发者工具 → 工程度量与质量分析"这一空白生态位，是 MoonBit 生态
  工程化能力的基础组件，与已有解析器、模板、日志等库互补而非竞争。
- **竞品与优势**：mooncakes 检索确认无同类 cloc 风格工具（模板/CSV/JSON Schema/图算法/
  日志等方向均已饱和，本方向空白）。相对通用 cloc，优势在于：纯 MoonBit 实现、可作为库
  嵌入 MoonBit 工程、对 MoonBit 语法（`#|` 多行字符串、`///` 文档注释、`guard` 等）有
  专属识别、输出可直接用于 MoonBit 赛事与 CI 场景。

### 二、交付范围与工程边界

- **交付**：库 API + CLI + 45 语言支持 + 复杂度/健康指标 + 四种报告格式 + 41 个测试 + 三平台 CI。
- **明确不做**：不做精确语法解析（按注释/字符串剥离的统计口径，与 cloc 一致，不做 AST 级
  语义分析）；不做代码生成/格式化；不承诺与 cloc 逐字节一致的统计（口径相近即可，已文档化差异）。

### 三、实现路径与技术理解

- **常见路径**：正则统计（误判率高）→ 逐行词法状态机（本项目采用）；按语言硬编码 →
  语言定义表驱动（本项目采用，新增语言仅需一条定义）。
- **实现路径**：语言定义表 → 行级 tokenizer 状态机（跨行块注释/多行字符串状态延续）→
  圈复杂度 token 流分析 → async 目录扫描（`@fs.walk`）→ 报告渲染 → CLI（argparse）。
- **独到理解**：统计准确性取决于"注释/字符串剥离"而非行数计算本身，故 tokenizer 需处理
  转义、raw 字符串、嵌套块注释与跨行状态；工程上以"自举（dogfood）"验证正确性——
  用 mooncloc 统计 mooncloc 自身（2261 行 MoonBit），并以 41 个单元/端到端测试 + 三平台 CI
  固化回归。
